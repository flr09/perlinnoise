Beschreibung:
Eine Motorenanordung soll Bewegungen ausführen. Die Motoren sind im linearen Abstand angeordnet, können über eine web ui in vielen Parametern angeglichen werden



Ziel
Eine Anordnung aus vier Schrittmotoren soll organische, nicht-periodische Bewegungen ausführen. Die Bewegungswerte werden aus einem Noise‑Feld (aktuell: Simplex/Perlin‑ähnlicher Noise) generiert und in Motorwinkel übersetzt. Das System läuft autark auf dem FYSETC E4 (ESP32) und wird über eine Web‑UI im Browser gesteuert (ohne zusätzlichen Raspberry Pi).

Mechanik / Aufbau

4 Motoren in linearer Anordnung (gleichmäßiger Abstand entlang einer Linie).

Die relative Position/Abstände bzw. der „Einflussbereich“ jedes Motors kann über Offsets in der Web‑UI angepasst werden (gedacht als virtuelle Abtastpunkte im Noise‑Feld, nicht als physisches Verschieben).

Jeder Motor soll innerhalb eines einstellbaren Winkelbereichs verfahren, z. B. ±300° (Gesamt 600°), abhängig von Mechanik (Endanschläge, Kabel, Getriebe).

Die Übersetzung von „Grad → Steps“ erfolgt über Steps per Revolution × Microsteps × ggf. Getriebe.

Elektronik / Firmware (Funktionsprinzip)

Controller: FYSETC E4 / ESP32, Treiber: TMC2209 (UART‑Konfiguration + STEP/DIR Ansteuerung).

Das Programm stellt einen WiFi Access Point bereit und serviert eine HTML‑Seite (UI) direkt aus dem Flash.

Über HTTP‑Requests (/set?...) werden Parameter gesetzt (Start/Stop, Speed, Pattern, Framesize, Contrast, Shape, Range usw.).

Die Firmware berechnet fortlaufend Zielpositionen pro Motor und steuert die Motoren über eine Stepper‑Library (aktuell: Konzept mit Zielpositionen und „run()“).

Bewegungslogik (Noise → Motorposition)

Grundidee:
Es wird ein 2D‑Noise‑Feld (Simplex/Perlin‑Noise) als „Landschaft“ verstanden. Ein virtueller Punkt („Flight Path“) bewegt sich durch diese Landschaft. Jeder Motor tastet an einer leicht versetzten Position ab, wodurch ähnliche, aber nicht identische Bewegungen entstehen.

Pipeline pro Update-Zyklus:

Pfadgenerator (wählt die Bewegung des Abtastpunkts im Noise‑Feld)

Muster: z. B. Linear (Wind), Circle (Loop), Figure‑8 (Organic)

Parameter: Geschwindigkeit, Winkel (linear), Radius (circle/8)

Noise‑Sampling je Motor

sample = noise( (flightX + offsetX)*framesize, (flightY + offsetY)*framesize )

Offsets erzeugen räumliche Variation zwischen Motoren

Noise‑Formung (Shaping)

Framesize = Zoom/Frequenz (Dorf ↔ Kontinent)

Contrast = Amplitude (Hügelhöhe)

Z‑Shape = Form/Gamma + optional Invertierung (spitz ↔ weich / Berge ↔ Täler)

Mapping auf Motorwinkel

Noise (−1…+1) → Zielwinkel (z. B. −300°…+300°) → Steps → Zielposition

Bedienung über Web‑UI (Stand heute)

Start/Stop des Gesamtsystems

Auswahl des Bewegungsmusters

Parameterregler: Geschwindigkeit, Richtung/Radius, Framesize, Contrast, Z‑Shape

(Optional/naheliegend) pro Motor: Offset, Invertierung, individueller Range/Nullpunkt

Hinweis (Recherche Simplex/Perlin):
- Simplex Noise (Gustavson) ist eine Alternative zu klassischem Perlin Noise; beide liefern kontinuierliche Gradient-Noise Felder.
- Kantenbetonung / "Ridged"-Look kann durch Betrag/Invertierung des Noise-Signals erreicht werden (vgl. ridged noise).
